# Research notes: depth, detail and pose models (2026-10-16)

## 1. Pixel 2: portrait depth from one camera

The Pixel 2 had one rear camera, yet made good portrait photos. It did this in three ways:

1. **Dual-pixel stereo.** Each pixel of the autofocus sensor is split into two photodiodes, so every shot is really two views about 1 mm apart. That tiny stereo baseline gives a coarse depth map.
2. **ML segmentation.** A convolutional network segments the person, giving clean edges and hair. Segmentation corrects the depth, rather than relying on depth alone.
3. **HDR+ burst merge.** Several frames are merged for low noise, and the blur is applied to the merged image.

**What carries over to the iPhone:**
- iOS doesn't expose the focus-pixel data, so step 1 isn't possible.
- iPhones get a coarse depth map from the multi-lens camera instead.
- Step 2 carries over directly.
  - **Done** in `SubjectDepth.swift`: Vision's foreground-instance mask (any subject), or person segmentation as a fallback, fixes the coarse depth. The whole subject sits at its own depth with crisp edges, and the blur focuses on the subject's box rather than the frame centre.

**Next step, if wanted:** a monocular depth network gives depth from a single 48MP frame on any lens. This would allow portraits at 48MP on the main lens, where the depth format is 12MP only.
- **Depth Anything V2 Small:** Apache-2.0. Apple publishes a Core ML conversion (~50 MB F16) on Hugging Face (`apple/coreml-depth-anything-v2-small`).
- **Apple Depth Pro:** sharper boundaries, but heavier, under a research licence.
- Either would replace the 320×240 live depth stream for stills.
- **Needs a ~50 MB model download, so I haven't added it.**

## 2. Project Indigo (Adobe, Marc Levoy, 2025)

Source: <https://research.adobe.com/articles/indigo/indigo.html>

| Indigo | Where cam cam stands |
|---|---|
| Underexposes more than most cameras, to protect highlights | RAW + film and Natural now keep the DNG's highlight headroom and tone-map it in (`developWithHeadroom`) |
| Merges up to 32 frames. Noise falls with √N, so it needs less smoothing and texture survives | Not done: Apple's Max processing already merges frames; see "Next" |
| Mild tone mapping, saturation and sharpening for an "SLR-like" look | Scan stage (no crushed shadows, real white point, original detail kept); the noise-sharpening pass is removed; loudness normalisation stops over-saturated looks |
| Multi-frame super-resolution from hand shake when zoomed 2× or more | Not done: zoomed shots are Lanczos-upscaled to 48MP (no new detail) |
| DNG plus a JPEG with an HDR gain map | DNG is kept (separate or combined); photos are SDR |
| Zero shutter lag in Photo mode | Apple's processed capture provides it |

**Next (bigger features):**
- **Multi-frame super-resolution for zoomed shots on Max.** Capture 4–8 frames, register them with Vision's homographic registration, splat them onto a 2× grid, and normalise. This is real detail from hand shake.
- **Night merge.** Capture N short frames and merge them robustly, keeping highlights.
- **HDR gain-map output.** Save the film as SDR plus a gain map from the RAW headroom, so photos glow on HDR screens like Indigo's.

## 3. Pose and subject detection: open-source models compared with Apple Vision

| Model | Points | Licence | Strengths | Cost on iPhone |
|---|---|---|---|---|
| **Apple Vision** `VNDetectHumanBodyPoseRequest` (in use) | 19 joints, 2D | OS, free | Neural Engine, no download, multi-person, fast | none |
| Apple Vision `VNDetectHumanBodyPose3DRequest` | 17 joints, 3D | OS | Real 3D angles (lean, turn) | none |
| Apple Vision animal body pose | cats and dogs | OS | Pets | none |
| **MediaPipe BlazePose** (Google) | 33 landmarks incl. heels, toes, finger tips; 3D world coordinates | Apache-2.0 | Hands and feet placement; very good single-person tracking | ~10–20 MB SDK |
| MoveNet Lightning / Thunder | 17 | Apache-2.0 | Fast, robust for movement | small (3–12 MB) |
| RTMPose (OpenMMLab) | 17 / 26 / 133 (whole body) | Apache-2.0 | Higher COCO accuracy than the above; whole-body variant has hands and face | Core ML conversion needed |
| YOLOv8/11-pose (Ultralytics) | 17 | **AGPL-3.0** | Detection and pose in one network | Licence forces AGPL on the app |
| Subject: Vision foreground mask / saliency (in use) | masks | OS | Any subject, no download | none |
| Subject: YOLO / RT-DETR detection | 80 COCO classes | AGPL / Apache-2.0 | Named classes (dog, bicycle…) for framing rules | 6–40 MB |
| Segmentation: MobileSAM / EfficientSAM | promptable masks | Apache-2.0 | Masks any tapped object | 10–40 MB |

**Recommendation: combine, don't replace.**
- Keep Apple Vision as the first pass: it's free, runs on the Neural Engine, handles several people, and does pets.
- Add BlazePose only when the Pose guide needs hands and feet, for checks like "feet apart" or "hand on hip". Run it on the main subject's crop, so it stays cheap.
- Use Vision's 3D body pose for lean and turn checks before adding any dependency.
- Avoid YOLO's AGPL in a closed build. It's acceptable only if the whole app is released under the AGPL.
